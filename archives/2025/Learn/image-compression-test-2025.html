2025 年快结束了，试试先进的图片编码

最后更新: 12月 21, 2025 作者: illlights 字数: 3k 预计阅读时间: 14min

Galgame 随机图 API 已经上线快三年了，虽然每部 Galgame 都只挑选几张或十几张，但游戏数量多起来，总量也来到了 GB 级别。这个级别下储存倒不是什么难事，但是考虑传输的请求量，流量费还是挺贵的。

当时刚开始写这个 API 的时候 AVIF 格式还是比较新的图片格式，我把这个项目当成 NodeJS 学习项目来写，没仔细考虑大量图片传输的情况，直接转成 AVIF 传出去就完事了。直到最近，我又要一些和图片储存相关的项目，还重新迈入了摄影圈，怎么发照片、怎么存照片又被提上台面；最近图片和视频编码格式不断演化，确实是重新考虑图片格式的好时机。

可惜我对图片编码的理论不甚了解，所以这里的测试只能使用生产级、易用的现有转换工具，从感知上对图片大小和图片质量进行评价。

为了覆盖多种使用场景（其实是我的多种使用场景），选取了游戏截图、Galgame CG、室内手办摄影（并非手办）、风景摄影每个场景各两张。

类别 文件名

游戏截图 鸣潮 1_9_2025 3_59_18 PM、鸣潮 9_27_2025 10_42_08 PM、Apex Legends 6_29_2024 4_15_55 PM

各个编码的参数也不进行微调，毕竟真实使用情况不可能一张图片调一个参，压缩参数均使用默认配置，只改变质量参数。选取了最先进的几种图片编码，JPEG，JPEG XL，AVIF，WebP，分别测试了质量为 100、80、50 的情况。

这里需要注意的是，JPEG 是典型的有损压缩格式，即使质量设置成 100 也会对图片造成不可逆的破坏性压缩。AVIF 和 WebP 理论上有无损压缩模式，但我没玩明白怎么进行无损压缩，经过检查发现我这组测试只有 jxl 是真无损压缩（压缩后 hash 不变）：

结果分析

我们先写结果，详细的测试参数和数据放在后面，想自己尝试或者验证结果的往下翻。

如果不细分图片类型，无损存档想要放心无损压缩直接使用 JXL，高质量有损格式使用 AVIF_100，中等质量有损格式使用 WEBP_80，低质量/缩略图使用 AVIF_50。

如果图片有明显的特征，只考虑图片大小，可以参考以下结论：

JPEG 有损压缩质量 100 对于相机拍摄的大图片压缩具有明显的优势。

Filename JPG_100 AVIF_100 WEBP_100
P1000025 19.65% 27.27% 22.02%
P1000042 24.56% 30.97% 23.12%
P1000122 24.13% 32.22% 25.93%
P1000200 26.54% 34.47% 27.75%

但是 JPEG 在游戏截屏、Galgame CG 这些类别中表现很差，并且在相机拍摄的大图片中的优势随着质量降低也会消失。

我觉得 JPEG 比较适合网络传输下非原图的高质量摄影作品图片。由于是有损压缩，不应用于存档；较低质量参数下压缩比率优势也不明显。

游戏截图和二次元 CG 比较适合使用 AVIF 格式，在二次元用 JPEG_100 和 WebP_100 还不如用 JXL 无损。

低质量下 AVIF 的图片大小最小，做缩略图比较合适。

需要尤其注意的是，每种压缩算法都不一样，质量参数相同不代表实际观感相同，各种算法的侧重点肯定也有区别。比如 AVIF 可能会使用 YUV 4:2:0 的色度采样，对色彩会产生影响，甚至出现明显色彩断层。所以接下来还会展示几个压缩后的图片，可以根据自己的实际观感感受一下图片压缩质量。图床不让上传 AVIF，想要对比下后面的压缩包或者自己看吧，这里的 AVIF 都是截屏之后又转成 WebP 的。

（ jxl 格式浏览器都不支持，现阶段我也建议只用来存档）

AVIF 格式压缩会有明显的色彩变化和动态范围压缩，即使是 100 也会存在色彩变化问题，在二次元图片里尤其明显（但是二次元图片的压缩率确实是高，需要自己权衡）。

这一张红色和脸上的颜色明显有区别。

这一张高亮部分也有可见的区别。

低质量参数下 AVIF 的噪点表现远好于其他压缩方式（甚至似乎还有莫名奇妙的降噪效果），最终的辨识度其实差不多。

对于 CG 和游戏截图，不放大看，50 质量也基本上没什么区别（除了 AVIF 的色彩）
